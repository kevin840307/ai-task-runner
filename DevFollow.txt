設計原則（必須遵守）

1. 最少 Code。沒有明確需求就不要新增抽象；舊概念無使用者就直接刪除，不保留相容層。
2. 24H 無人值守優先。預設 `stage_retries=-1`，技術異常可持續重試；API/服務異常必須使用「秒」為單位的 delay/backoff。
3. Workflow 只有 Stage nodes + PASS/FAIL semantic edges；ERROR 不是 graph edge，由 StageExecutor technical retry/recovery 處理。rollback/loop 就是 PASS/FAIL edge，不存在 recover/restart_at/repeat/repair runtime object。
4. Stage 只做工作並回傳 StageResult。新增 Stage 不得實作 retry/recover/session rotation。
5. StageExecutor 是 Stage 技術可靠度唯一 owner：Hook、安全、changed files、Same Session retry、Fresh Session rotation、retry delay。
6. 正常 AI 流程優先 Same Session，只補新 evidence；Fresh Session 才重送完整但必要的 Stage context。
7. 每個 Session 的失敗嘗試必須 bounded；目前預設 2 次後只 Fresh 該 Stage 的 session，再繼續同一 Stage。
8. Final AI validation 每個 vote 必須使用不同 Fresh Session。
9. Deterministic configuration/state/snapshot/programming error fail closed，不得進無限 retry。
10. 已修改 maintained source 的 failed write attempt 不可盲目重做，交由 Review/Validator/result edge 判斷。
11. KeyboardInterrupt/SystemExit 不可被 retry/recovery 吞掉；cleanup 後必須原樣往上傳遞。
12. Process Supervisor 只負責 process-level crash/hang/resume/ownership/orphan cleanup，不複製 Stage retry policy。
13. Worker hard crash 後 orphan cleanup 必須使用實際 durable work path，Direct 與 YAML List child 都要涵蓋。
14. Active/Resume Run 必須凍結會影響 AI 行為的 Workflow、Prompt、Goal、Final-AI Prompt；YAML List child 同樣適用。
15. Prompt 使用 bounded context。Same Session 不重送 Goal/Rules/完整 contract，只增加新 TODO/Review/Validator/error evidence。
16. Backend parity：完整 Agent Prompt 走 stdin；session/sandbox/permission/error parsing/timeout identity 屬於 Backend adapter，Workflow/Stage 不 branch Qwen/OpenCode。
17. Global 資產統一放 `runner/assets/workflows/*.yaml` 與 `runner/assets/prompts/<category>/*.md`；Project 使用 `<project>/.ai-task-runner/assets/workflows/` 與 `prompts/`，兩邊 shape 相同且可編輯。
18. UI 是同一張 n8n-style graph 的編輯器；CLI/API/YAML List 都只是 RunRequest adapter，不可擁有第二套路由或 recovery。
19. Dry Run 必須重用正式 Workflow Loader + FlowEngine，只 mock Stage result。
20. Plugin 只有一個 discovery boundary：`runner/plugins/registry.py`；外部統一使用 `ai_task_runner.plugins`。
21. Plugin 若要註冊 Stage/Backend 使用 `setup()`；runtime Hook 使用 `register(runtime)`。Workflow 不感知具體 Plugin。
22. protected/readonly fingerprint 只追 maintained project source；`.git`、`.ai-task-runner`、IDE/build/test/cache artifacts 使用共用 ignore policy 排除，但 `.gitignore`、`.github/**`、`.editorconfig` 等正式檔案仍需追蹤。
23. Log 精簡但足夠 Debug；所有長輸出必須 bounded。
24. 名稱、folder、owner/import path 必須直觀；一個能力只保留一個 owner。
25. Dynamic Handoff 是唯一 multi-agent runtime primitive；未來 Parallel 若真的需要，必須重用 Stage、StageExecutor、StateStore、Plugin boundary、Workflow asset 與 Graph Designer，不得先建立第二個 Orchestrator。
26. 文件、範例、UI、CLI、YAML、Dry Run 與測試必須與正式 runtime contract 同步，不允許 legacy contract 留在測試裡。
27. React Full Designer 唯一可維護 source 是 `ui/studio-src/**`。禁止直接修改 `ui/static/workflow-studio-app/**`；該目錄只能由 `cd ui/studio-src && npm run build` 產生。若 compiled output 需要提交，也只能提交 build 產物，不可手修 minified JS/CSS。
28. Full Designer 的返回行為必須 deterministic 回到主 UI 的 Workflow Studio，並盡量重新開啟同一 Workflow；禁止依賴 `history.back()`。
29. 只有實際通過 Windows + Ubuntu CI、real-Qwen reliability probes 與必要 soak 證據後，才可宣稱 24H 重構完成。

核心：Stage 做事；StageExecutor 讓 Stage 穩定；FlowEngine 決定下一步；StateStore 讓進度可 Resume。


Workflow UI ownership
- Project Chat is the primary run surface.
- Workflows and Prompts are separate primary navigation workspaces.
- Workflows manages Workflow assets and opens the single Workflow Editor.
- Prompts owns Prompt asset management and Prompt Editor.
- Workflow Editor is the single Workflow editing surface with Designer/YAML views over canonical YAML.
- Stage settings may expose Form/YAML/Routes/Test, but all views update one Stage draft and use backend YAML/schema validation.
- Do not reintroduce a second Visual Workflow editor in the asset library.
- ralphy_ai_validate.yaml is the Chat fallback default when no valid saved Workflow preference exists.
- Workflow Library right-click owns Show in Chat / Hide from Chat; reuse persisted workflow visibility and never create another visibility store.
- Stage Editor tabs are Form / YAML / Routing / Test. Form and YAML edit the same Stage draft; routing stays graph-owned.
