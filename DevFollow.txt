設計原則（必須遵守）：

1. 最少 Code，禁止 Hardcode(Global通用的不算)。
2. 不影響現有 24H 穩定執行，包含 YAML List 任務。(預設參數就是24H穩定運行到過, 不能中途停下)
3. Log 精簡但足夠 Debug。
4. 低耦合：Workflow 不感知 Extension/Event，擴充功能一律 Plugin 化。
5. 正常流程優先 Same Session，只補新資訊，不重複 Context。
6. AI 最終驗證使用 New Session，然後假如需要驗證三次，這三次都要是不同的Session。
7. 驗證異常先 Same Session Recover，最多 Retry 2(default可更改) 次；仍失敗才 New Session。
8. New Session 才提供完整且必要的 Context。
9. Workflow 必須易於新增、移動、替換與擴充 Stage。
10. 能瘦身就瘦身, 減少不必要的Code
11. 程式碼需要容易懂，直觀，人好維護
12. 移除舊程式碼、不必要的程式碼
13. ai agent輸入prompt應該都要使用stdin, 防止cmd超出文字
14. 檔案&function命名合理、易懂、folder分類合理、拆分合理
15. plugins容易新增和擴充
16. 文件要有中英版本, 要詳細一點並且跟現有功能有對齊
17. retry -1則是測試到過為止, 但還是要遵守5. 6.
18. workflow stage一樣要容易擴充和好維護, yaml也是, 一眼就能懂, 人類容易修改
19. Recovery 的 failure identity 必須穩定且具語意；PID、timestamp、container/session 名稱等動態 log 只能用於 Debug，不可讓同一 failure 被誤判為不同 failure。
20. 公開能力只保留一個明確 owner/import path；沒有 validation、lifecycle、isolation 等責任的純 re-export 暴露層應移除。
21. KeyboardInterrupt/SystemExit 不可被 Stage retry/recovery 吞掉；中斷前可做必要 cleanup，但必須原樣往上傳遞。
22. Worker hard crash 後的 orphan cleanup 必須依實際 durable state/work 路徑處理，Direct Run 與 YAML List child 都要涵蓋。
23. Deterministic Resume／snapshot／configuration 錯誤不可進入無限 retry；只有可能隨時間恢復的 runtime/service failure 才能持續 recovery。
24. Active／Resume Run 必須凍結所有會影響 AI 行為的 file-based input，至少包含 Workflow／Stage Prompt／Goal File／Final-AI Prompt；YAML List child 亦同。
25. Stage recovery 只傳必要的新 evidence；structured Stage 結果透過 bounded `previous.data` 傳遞，Prompt Context 必須限制大小，不可因 recover 重送大量既有內容。
26. Backend parity: complete AI task prompts must use stdin. Session, sandbox/permission, error parsing, and timeout identity belong to each Backend adapter; Workflow/Stage must not branch on Qwen/OpenCode.
27. Builtin 正常 Same Session 若已看過同一 Stage Prompt contract，只能透過 bounded continuation 補新 TODO／Review／Validator evidence；不得重送 Goal、Rules 或完整 Stage contract。對應 contract 必須由 deterministic test + qwen_live_reliability 鎖定。
28. Example／Demo 執行不得污染 canonical fixture；單一 Example 只複製該 Example 到獨立 workspace，`--all` 才複製 examples 集合，不複製整個 Runner repo。每次 Run 都重新建立副本；預設放在 `.example_runs/`，可由環境變數覆寫並保留 work path 供 Debug。
29. `max_results` 是 FlowNode 的 opt-in semantic-result 上限：未設定時既有 Workflow 行為完全不變；只有成功產生合法 PASS/FAIL StageResult 才計數，timeout／API／backend／parser／structured retry／session recovery 等技術異常不計數；計數必須 durable，Resume 不可重置。
30. `status` 屬於可重用 Stage 的通用執行狀態；FlowNode 若需描述本次具體工作使用可選 `label`。`label` 只作 runtime/UI/log metadata，不可改變 Stage、Prompt、Retry、Session 或 routing 行為；未設定時保持既有行為。
核心：最少 Code、零 Hardcode、低耦合、可插拔、易擴充、可 Debug、24H 穩定。
