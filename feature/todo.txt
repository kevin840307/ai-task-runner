0. 不可違反的設計原則
----------------------

[ ] 保留目前 AI Task Runner 的 UI 視覺語言，改善原有介面，不另造一套陌生的 ChatGPT 外殼。
[ ] Chat 負責對話、排隊與釐清；Task 負責工作紀錄；Runner Core 負責執行、Stage 路由、Retry、Recovery、Resume 與真實 Runtime 狀態。
[ ] Chat 不能因一般對話而偷偷建立或啟動 Runner Task。
[ ] UI、CLI、YAML、API、Dry Run 必須共用同一份核心契約，不可各自實作第二套排程或復原邏輯。
[ ] Task Draft 是暫存規劃資料，不是已建立 Task，也不能帶入假 Runtime / 假執行結果。
[ ] 一般 TaskDraft / Create Task 建立後進入 New / idle；只有使用者明確輸入 @goal 時，才允許以單一明確動作 Create + Run，且必須沿用同一 Runner action contract。
[ ] 目前 UI/Task flow 的 Auto / Main / Isolated Worktree 共用同一 Workspace resolver，皆先建立 isolated worktree 再 trigger Runner；CLI/standalone Runner 仍只吃 caller-supplied project_root，完全不依賴 Workspace/Worktree/Git integration。
[ ] Main 完成定義：Runner Complete 只代表 Runner 階段完成，Task 仍是 Ongoing；commit local Task branch 後直接 normal merge 到 captured Project branch，merge 成功後才 Closed · merged。若 real merge fail：abort → merge_failure_count +1 → 讀 Global Settings.merge_failure_limit；count > limit 則 fallback 為 Isolated Worktree · Closed · worktree_ready。
[ ] 無法使用的按鈕必須 disabled 並說明原因；Backend 仍要再次驗證，不能只依賴 UI。
[ ] 避免 Dialog 疊 Dialog、俄羅斯娃娃式流程與重複資料副本。
[ ] 優先處理 24H 無人值守可靠性、恢復能力與可診斷性，不為 UI 功能另造 Scheduler / Recovery Engine。

6. Chat Queue（對話排隊）
-------------------------

[x] Queue 與 Runner Task List 是完全不同的概念；Chat Queue 只保存尚待送給目前 Chat Agent 的 Prompt。
[x] Queue 以 Chat session 為單位儲存，切換 Project / Chat 不可串錯。
[x] 有 Agent turn 執行中時，使用者送出的後續 Prompt 應依 Agent 原生能力加入 Queue；若 Agent 沒有原生 Queue，Backend 提供相同產品契約。
[x] Queue 項目直接顯示在 Composer 上方；沒有項目時整塊隱藏，busy 時另顯示自動排隊提示。
[x] 每個項目顯示順序、可閱讀的摘要與 Edit / Delete。
[x] Edit 使用 inline editor 或精簡的同一區塊，不再開一個大型 Modal；Save / Cancel 都要有效。
[x] Queue 項目不能為空；儲存失敗時顯示明確錯誤並保留原值。
[x] 預設 FIFO，除非 Agent 原生介面明確提供不同順序契約。
[x] 以 Qwen Code 原生 queued-next-turn / Ctrl+Q 為 UX 參考；正式 Web Chat 在 Agent busy 時以 Ctrl+Q 重用同一 Chat turn → Backend FIFO Queue contract，不模擬或注入 CLI 鍵盤事件，也不另造 Queue scheduler。
[x] Prototype 不提供 Queue 按鈕；Mock 模擬 Agent busy，連續按傳送會自動排隊，並可編輯／刪除多筆 Queue。Ctrl+Q 只保留為 busy 時的可選快捷鍵。
[x] Deterministic Browser/API fixture 支援新增多筆、編輯、取消編輯、刪除、空白驗證、長訊息、切換 Chat session，並驗證舊 session Queue 不被新 Chat 污染。
[x] Backend 擁有 Queue 的真實順序、持久化與出隊狀態；UI 只顯示 Backend projection。
[x] Agent 取消、session 過期、API 錯誤或使用者重啟後，不得無聲遺失未處理 Queue 項目。
[x] 定義 Queue item 狀態（至少 queued / dispatching / completed / failed / cancelled），避免 UI 自行猜測是否已送出。


7. AI Ask / Clarification（反問使用者）
--------------------------------------

[x] Ask 指的是 Agent 在目前工作過程中遇到需要使用者決定的事項，暫停目前 turn 並向使用者提問。
[x] Ask 不是 Qwen /btw 這種獨立 side question；/btw 保持為 Agent 原生能力。
[x] 統一 Ask 問題資料格式，避免 Qwen 與 OpenCode 各做一套前端流程。
[x] 一次 Ask 可以有多個問題；每題可為選項題或自由文字題。
[x] 選項題最後固定提供「其他／自行輸入」，選擇後顯示文字輸入框。
[x] 選項題未選選項、Other 沒填文字、文字題空白時，不可 Next / Submit。
[x] 每題顯示目前進度；使用者回答後按 Next；最後一題顯示 Submit。
[x] Submit 將所有答案組成一份結構化 answers object，回傳給原本等待中的 Agent tool call，然後續跑同一個 turn。
[x] Cancel 必須回覆明確的 cancel / deny 給待處理的 Agent question，不能捏造答案，也不能讓 turn 永久掛起。
[x] 正式版 Ask 卡片嵌入 Chat 訊息流，選項清單有獨立捲動區，不使用遮住訊息的浮層。
[x] Ask 是否可用由 Agent adapter capability 決定；Project Chat Settings 顯示 Native / Unavailable 與原因。Qwen 依已驗證 native Ask 版本契約判定，OpenCode probe question.list；不再由前端假設支援。
[x] OpenCode adapter 對應原生 question tool 的 header / question / options / custom answer 與多題 Submit 行為。
[x] Qwen Code adapter 對應 ask_user_question 的 questions[] 與按索引對應的 answers；若當前版本能力不同，依實際 Agent contract 調整。
[x] Ask request 綁定目前 Chat session、Agent turn 與 request ID，避免使用者切換 session 後答案送錯 turn。

11. Workspace / Worktree
------------------------

[ ] Workspace policy 保留 Auto / Main / Isolated Worktree。
[x] Prototype 的 Auto 已讀 Global Auto workspace policy；所有已知 Run 入口共用 prepareTaskWorkspaceForRun / resolveTaskWorkspace。
[x] Prototype `Allow concurrent Main tasks` 預設 Off；Off 維持 Main busy 禁選/阻擋，On 時 resolver 與 Main selector 都解除 busy 限制。
[ ] 正式版 UI/Task flow 三種模式一律先建立獨立 Task Run worktree/local branch 再呼叫 Runner；這是外層 orchestration 規則，不是 Runner contract，CLI Runner 仍可直接跑任意 caller-supplied project_root。
[ ] Project branch 是 canonical truth。
[ ] Task Run 啟動時捕捉 target_branch + target_head_sha_at_start；不可 hardcode main，也不可因使用者之後切 branch 偷偷 retarget。
[ ] Task branch/worktree 直接從 captured target HEAD 建立；branch/path 使用 Task + Run identity，例如 local/task/T-001-r2、.worktrees/T-001-r2。
[ ] Uncommitted Project working-tree 修改不自動進 Task base；要成為新 Task base 先 commit。
[ ] Auto policy × Concurrent Main 規則固定如下：

    | Auto policy / selection | Main 已 Running | Concurrent Off | Concurrent On |
    | --- | --- | --- | --- |
    | Busy project → Worktree / Auto | yes | Isolated Worktree | Isolated Worktree |
    | Always Main / Auto | yes | Block Main start | Main |
    | Always Worktree / Auto | yes | Isolated Worktree | Isolated Worktree |
    | Explicit Main | yes | Block Main start | Main |

[ ] Concurrent Main 開關只控制 Main busy 時能否啟動 Main；不可改寫 Auto policy。
[ ] Concurrent Main=On 時多個 Main Task 可在各自 isolated worktree 平行跑；同 target branch direct merge 仍排隊。
[ ] Workspace resolver 是唯一決定 target branch / Task worktree / branch identity 的來源；UI 不自行拼正式路徑。
[ ] Stop / Resume / Restart / process recovery 保留同一 Task Run workspace identity。
[ ] Runner Complete snapshot / cleanup 前必須驗證 worktree registration、repo identity、expected Task branch、expected source-base ancestry、無 active merge/rebase/cherry-pick/revert/bisect；不符即 fail closed，不能自動 switch/猜 branch/rewrite history。
[ ] Task 刪除、Reset/Rerun、Run 完成與 Worktree cleanup policy 分開；不能默默刪 retained/unmerged 結果。


11. Workspace Results / Direct Merge
------------------------------------

[ ] 詳細 source of truth 使用 feature/git-worktree-todo.md；正式流程只保留 Project branch → Task worktree/local branch → Runner → local commit → direct normal merge → finish / fail recovery。
[ ] effective Main：Runner Complete 後 git add -A + commit remaining changes 到 local Task branch；此時 Task 仍 Ongoing。
[ ] effective Isolated Worktree：Runner Complete 後 commit result，直接 Closed · worktree_ready，不自動 merge。
[ ] Main merge queue 以 repository + captured target branch 序列化；Runner execution 可平行；Runner Complete 有 deliverable commit 時原子分配 durable FIFO merge_queue_seq，restart 必須保留順序；queue head 在 conflict Runner recovery 期間保留順位，但短期 Git lock 必須釋放。
[ ] Main merge 前先檢查 merge_source_sha 是否已是 target branch ancestry；是則 idempotent finalize merged，不重複 commit；否則在 captured target worktree 執行 `git merge --no-ff --no-commit <merge_source_branch>`，保持可 abort，configured merge validation PASS 後才 git commit，merge success 才 Closed · merged。
[ ] merge validation 必須 verdict-only / source-non-mutating，統一 PASS / SOURCE_FAIL / TECHNICAL_ERROR；Git conflict 或 SOURCE_FAIL 才算 real merge fail，真正 source repair 只在 recovery worktree 透過 Runner 執行；TECHNICAL_ERROR abort merge 但不增加 merge_failure_count。
[ ] real merge conflict / SOURCE_FAIL：git merge --abort → merge_failure_count += 1 → 記錄 structured failure。
[ ] Task 只保存實際 merge_failure_count；Global Settings 只保存 merge_failure_limit。
[ ] 每次 real merge fail 後讀 Global merge_failure_limit：count <= limit → existing Runner 基於 latest Project branch 重做/Recovery → commit recovery branch → 原子更新 merge_source_branch / merge_source_sha / merge_source_worktree → retry direct merge；之後不可再 merge stale original Task source。
[ ] merge_failure_count > Global limit → 停止 automatic Main merge，保留最新 current merge source branch/worktree，fallback=isolated_worktree，Closed · worktree_ready，reason=merge_failure_limit_exceeded。
[ ] queue wait、merge lock busy、target dirty/unavailable、transient Git error、Runner 在下一次 merge 前失敗都不增加 merge_failure_count。
[ ] Recovery worktree/branch 只有真實 merge fail 且需要改 Code 才建立；不是 normal integration layer。
[ ] Recovery Runner 必須帶 original Task intent、Task base/snapshot SHA、latest target HEAD、conflict files、Git error、Project dev rules。
[ ] target checkout dirty => Ongoing · waiting_target_clean / Needs Attention；不可 auto-stash/reset/discard/stage/commit 使用者修改。
[ ] captured target branch 無安全 managed worktree，或被 unmanaged/user worktree checkout => Ongoing · waiting_target_workspace / Needs Attention。
[ ] captured target branch 被刪除/rename => Ongoing · waiting_target_branch / Needs Attention；不可自動 recreate、猜 main、或 retarget。
[ ] target force-reset/divergence 後若 merge_source_base_sha 不再是 current target HEAD ancestor => Ongoing · waiting_target_history / Needs Attention；不可 direct merge/recovery，也不增加 merge_failure_count，避免把被移除 history 重新帶回來。
[ ] 不得自動 git switch 使用者 Project checkout。
[ ] Main completion boundary：current merge_source_sha 已成為 target branch ancestry 且 merged_target_head_sha 已持久化；no_changes 是唯一正常免 merge 例外。
[ ] Restart 時恢復 durable merge_queue_seq + current merge source；若 merge_source_sha 已是 target branch ancestor，直接 finalize Closed · merged，不可重複 merge；若留下本系統未完成 merge state，先 ownership reconcile 後安全 finalize/abort。
[ ] Workspace Results 顯示 Project / Task Run、target branch、source branch/path、merge_status、merge_failure_count、fallback/conflict summary。
[ ] Board 維持 New / Ongoing / Paused / Closed；Main merge 是完成流程的一部分，不是 Closed 後的 post-processing。
[ ] UI 不新增 top-level Git Worktree 主頁；日常走 Task Info，Project Workspace Results 管 retained/fallback worktree。
[ ] Remote push 是獨立 Publish action；正常 lifecycle 沒有 local push，也不自動 git push origin。
