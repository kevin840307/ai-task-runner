1. 最終目標
===========

用最少程式碼完成可 24H 無人值守的閉環 Runner：

UI / CLI / API / YAML List
            |
         RunRequest
            |
     WorkflowRunner
            |
        FlowEngine
       /         \
StageExecutor   StateStore
      |
    Stage

核心原則：
- Stage 是唯一執行單位。
- Workflow 只定義 Stage nodes + PASS/FAIL/ERROR result edges。
- rollback / loop = edge 回到前一個 Stage。
- Stage 不處理 retry / recover / session rotation / routing。
- StageExecutor 統一處理 technical retry、Same Session、Fresh Session、timeout、API transient。
- stage_retries=-1 = technical failure 可無限重試。
- API/服務 transient retry 使用「秒」為單位 delay/backoff。
- FlowEngine 只處理 semantic graph navigation。
- StateStore 只保存 Resume 必要 durable state。
- 不建立第二套 Runner / Pipeline / Recovery framework。

6. Folder 合併決策
=================

目前不建議再硬合併 major folders。

KEEP:
- agent/：AI client/session/provider adapter
- workflow/：graph + Stage semantics
- runtime/：durable/process reliability
- plugins/：extension/hook boundary
- assets/：editable assets
- config/：RuntimeConfig/defaults

只有符合以下三條才再合併檔案：
1. 只有一個明確 owner；
2. 主要只是薄 wrapper/helper；
3. 合併後能減少 navigation，且不會產生 mixed-responsibility 大檔。

禁止用「folder 越少越好」作為重構理由。

8. Future - 現在不要做
=====================

UI 最終支援三種 family：
1. Linear Workflow with Rollback / Loop   <- current
2. Dynamic Handoff                       <- future
3. Discussion / Group Chat               <- future

共同產品入口永遠：
Choose Workflow/Profile -> Prompt -> Run

未來 Dynamic/Discussion 必須重用：
- Stage
- StageExecutor
- StateStore
- Plugin boundary
- Asset layout
- Graph Designer

只有真的出現第二種 scheduling semantics 時，才抽最小 scheduler state。
不要現在先建立 UniversalAgent / GenericGraph / 多套 Orchestrator。


9. 完成定義
===========

這次大重構只有在以下全部成立才算完成：

- 新增 Stage 只需 Stage work/result code。
- Stage 不含 retry/recover/session/routing。
- rollback/loop 只由 result edge 表示。
- API/service transient 可 stage_retries=-1 無限重試，且使用秒數 delay/backoff。
- Prompt categorized key 不衝突。
- UI/CLI/API/YAML List 共用同一 runtime。
- Dry Run 共用 production FlowEngine。
- Windows CI PASS。
- Ubuntu CI PASS。
- real-Qwen reliability probes PASS。
- 24H soak PASS。
- 無 stuck state / orphan process / unbounded growth。
- README / architecture / DevFollow / future.txt / todo.txt 與實際 code 一致。
