AI Task Runner - Current TODO
=============================

Branch: minimal-closed-loop-runtime

GOAL
----
Keep the product small, understandable and reliable for 24H unattended runs.
The architecture refactor is complete. Do not restart old architecture work unless
a reproduced failure proves it is necessary.

Current runtime capabilities:
- Dynamic Handoff is supported and remains part of the current runtime.
- Discussion / Group Chat remains intentionally removed.

Core runtime ownership stays:
- WorkflowRunner = composition / entry
- FlowEngine = semantic PASS/FAIL/HANDOFF navigation + dynamic child Workflow
- StageExecutor = technical retry/session/recovery/timeout/safety
- Stage = semantic work only
- StateStore / RunState = durable resume state
- YAML = canonical Workflow contract
- ERROR is not a graph edge

Do not restore removed contracts:
scope/task-level workflow, public type: task/review, repair Stage, routes.error,
recover graph route, restart_at, repeat, max_attempts/on_exhausted,
alternate TaskRunner/Pipeline runtimes, Discussion/Group Chat compatibility.
No public scope / task_step / type: task / type: review compatibility contract remains.

CURRENT PRIORITY
----------------
Do not add features just because they are possible.
Prioritize by:
1. impact on common usage,
2. impact on 24H unattended reliability,
3. reduction of user confusion / operator mistakes,
4. implementation cost and regression risk.

UI/UX reference direction:
- n8n / Langflow / Flowise / Dify are references for interaction patterns, not feature targets.
- Borrow only patterns that reduce mistakes or debugging time.
- Keep this product centered on Tasks + Workflows + Prompts; do not copy platform-scale navigation.
- Keep YAML canonical and explicit Save validation. Do NOT auto-save canonical Workflow YAML merely because other editors auto-save drafts.

WORKFLOW DESIGNER CURRENT CONTRACT
----------------------------------
- PASS / FAIL / HANDOFF edges may be connected, deleted and retargeted freely.
- Deleting PASS must not silently continue to next.
- Flow order may compactly serialize PASS-to-next.
- ERROR remains error_policy, never a graph edge.
- START/END are UI-only.
- Save backend validates flow/routes/targets/schema before writing YAML.
- Unsaved editor recovery, if implemented, is a local draft only and never bypasses Save validation.
- Runtime executes only canonical saved YAML.
- Stage Test does not create a second execution model.

LIVE REGRESSION NOTES
---------------------
[x] Fixed API outage recovery observability false failures.
    - Root cause: the live gate treated transient UI status (runner.status=Recovering)
      and a 100ms polling observation of durable last_error as mandatory evidence.
      Fast successful recovery can complete between polling iterations even when Runner
      correctly retries and clears last_error.
    - StageExecutor now publishes stable structured runner.recovery/retry events carrying
      stage, retry_mode, retry number, wait_seconds and error, while still emitting the
      transient Recovering UI status.
    - 429/502/503/raw-disconnect probes use the structured recovery event as the
      StageExecutor recovery contract and always perform a final JSON/log scan after process exit.
    - Successful recovery must still finish in the same session and leave final last_error empty.
    - Deterministic StageExecutor tests assert both UI Recovering status and structured recovery
      payload; live harness tests lock the post-exit scan to prevent fast-recovery races.

[x] Strengthened transient API recovery live proof to distinguish backend retry from Runner recovery.
    - The live probe now latches durable state.last_error while the outage is active, which proves the
      failure actually crossed the backend boundary and reached StageExecutor.
    - Recovering structured status is observed from the probe-owned --json-events console stream first,
      with bounded production log.txt as secondary evidence.
    - Failure diagnostics now distinguish: outage absorbed below StageExecutor vs StageExecutor recovery
      without structured Recovering observability.
    - Successful completion still requires same-session recovery, no RESET_SESSION verdict and final
      durable last_error cleared.
    - The same shared probe covers HTTP 429/502/503 and raw disconnect variants.

[x] Fixed transient API recovery live false failure caused by bounded-log observation.
    - Root cause: Recovering is a short-lived runner.status event, while log.txt is intentionally bounded.
      api_recovery_probe waited until the whole run completed, then required the final bounded log to
      still contain that earlier UI state. A valid same-session recovery could therefore pass all runtime
      checks but fail the harness if the early event had already been trimmed.
    - The probe now latches Recovering evidence while the outage/retry is actually active.
      Final assertions still require same-session recovery, no RESET_SESSION verdict, successful completion,
      and durable last_error cleared.
    - The shared api_recovery_probe covers HTTP 429/502/503 and raw-disconnect variants, so the race fix
      applies consistently across those live probes.
    - Added deterministic harness contract coverage; runner retry semantics were not weakened.

[x] Fixed Dynamic Handoff session_policy=main live false failure after successful completion.
    - Root cause: finish_run intentionally clears state.ai_session_id and the primary AI client session
      after Workflow PASS, but the older live assertion treated a cleared final ai_session_id as failure.
    - The live probe now forces main_role through a deterministic gate twice and verifies both real
      model.result session ids are identical during execution.
    - After completion it requires the primary durable session to be cleared, matching finish_run.
    - role/fresh policies remain independently checked through stage_sessions and real model session ids.
    - Added deterministic contract coverage for primary-session cleanup.

[x] Reworked Dynamic Handoff session_policy=main live proof to test direct reuse instead of final-state retention.
    - The previous probe ran main_role only once, then required final completed state.ai_session_id to equal
      that one model session. Primary-session durability across process restart is already owned by the
      dedicated resume/process-restart probe.
    - Dynamic Handoff now deterministically visits main_role twice through main_gate and verifies the two
      real model.result session ids are identical. stable_role is still visited twice to prove role reuse;
      fresh_role remains isolated and non-durable.
    - If final state.ai_session_id is present it must agree with the observed main session, but the probe no
      longer falsely fails solely because a completed run does not retain it.
    - Deterministic fixture/dry-run/gate coverage was updated to include the two main_role visits.

[x] Fixed real Review Stage Probe false failure caused by incomplete isolated review evidence.
    - Root cause: the live Stage Probe created a Review Task with an empty deliverable/last_output,
      while the harness still expected PASS->done. Real Qwen correctly returned semantic FAIL->stop
      because there was nothing concrete to verify.
    - Isolated Review Stage tests now populate the supplied input as deliverable and executor evidence
      with a concrete acceptance criterion. Production Review semantics are unchanged.
    - The real-Qwen preflight now supplies a deterministic completed-evidence token and requires
      PASS + route=next + next=done. FAIL->stop remains the correct default routing contract when
      Review evidence is actually incomplete.
    - Added deterministic Stage Probe/source contract coverage and live harness contract coverage.
    - Other real Stage Probe assertions were audited; no additional model-result-forcing scenario remains.

[x] Fixed Dynamic Handoff live route false failure caused by LLM-controlled visit counting.
    - Root cause: the probe required stable_role to emit STABLE_FIRST on its first call and
      STABLE_REPEAT on its second call, then used those exact model outputs to decide whether
      the coordinator should visit stable_role again. A valid real-Qwen run emitted the later
      token on the first call and legally advanced to fresh_role, so the harness failed even
      though Dynamic Handoff completed successfully.
    - The probe now uses Dynamic Handoff only for the real model-selected main_role entry.
      A deterministic Command Stage gate forces stable_role to execute exactly twice
      (first exit=1 -> semantic FAIL -> stable_role, second exit=0 -> PASS -> fresh_role).
    - role-session reuse is verified directly from the two real model session ids instead of
      inferred from model wording; fresh/main isolation remains independently verified.
    - Added deterministic fixture/gate coverage. No other invocation-count-controlled LLM
      routing probe remains in qwen_live_reliability.py.


[x] Dry-run now accepts --max-cycles and has a regression that proves a backward loop reaches max_cycles_exhausted at the same cycle boundary as production FlowEngine.
[x] API outage live probes require structured runner.recovery/retry evidence, same-session recovery, and final durable last_error cleanup after success.
[x] Fixed Dynamic Handoff live startup failure caused by stale harness validator injection.
    - Root cause: runner_command() unconditionally added --validator validation.py to every direct run.
      Explicit Dynamic Handoff workflows without validate_file are correctly valid, but RuntimeConfig
      rejects a supplied file validator when the workflow has no validate_file Stage, so startup failed
      before state.json existed.
    - Explicit Workflow live commands now add --validator only when the loaded Workflow actually contains
      validate_file. Default runs keep their validator contract; file/mixed explicit workflows still receive it.
    - Added deterministic coverage for both sides of this contract.
    - Dynamic Session live fixture now preloads through the production Workflow loader and verifies local
      prompt resolution before touching Qwen.
    - assert_state_completed now includes the newest harness console tail when startup fails, eliminating
      low-information stage=None/cycle=None failures.

[x] Fixed detached-UI stop.request/resume live false failure.
    - Root cause: the probe required model.prompt(session_mode=resume) after every detached stop.
      stop.request can legitimately arrive after the AI Stage already checkpointed, while a
      command/validator is active, so Resume may complete without another model prompt.
    - stop_request_resume_probe now verifies the contract it owns:
      clean Supervisor exit=130, control-file cleanup, durable run/checkpoint preservation,
      no backward progress, durable AI session not erased, then successful --resume completion.
    - resume_probe remains the dedicated real-Qwen same-session transport proof at a
      deterministic checkpoint guaranteed to require another AI call.
    - Deterministic coverage proves Supervisor stop.request does not mutate state.json and
      the live harness accepts a valid detached Resume that needs no redundant model prompt.
