AI Task Runner - Current TODO
=============================

Branch: minimal-closed-loop-runtime
Repository: kevin840307/ai-task-runner

GOAL
----
Keep the product small, understandable and reliable for 24H unattended runs.
The architecture refactor is complete. Do not restart old architecture work unless
a reproduced failure proves it is necessary.

Current runtime capabilities:
- Dynamic Handoff is supported and remains part of the current runtime.
- Discussion / Group Chat remains intentionally removed.

Core runtime ownership stays:
- WorkflowRunner = composition / entry
- FlowEngine = semantic PASS/FAIL/HANDOFF navigation + dynamic child Workflow
- StageExecutor = technical retry/session/recovery/timeout/safety
- Stage = semantic work only
- StateStore / RunState = durable resume state
- YAML = canonical Workflow contract
- ERROR is not a graph edge

Do not restore removed contracts:
scope/task-level workflow, public type: task/review, repair Stage, routes.error,
recover graph route, restart_at, repeat, max_attempts/on_exhausted,
alternate TaskRunner/Pipeline runtimes, Discussion/Group Chat compatibility.
No public scope / task_step / type: task / type: review compatibility contract remains.

CURRENT PRIORITY
----------------
Do not add features just because they are possible.
Prioritize by:
1. impact on common usage,
2. impact on 24H unattended reliability,
3. reduction of user confusion / operator mistakes,
4. implementation cost and regression risk.

UI/UX reference direction:
- n8n / Langflow / Flowise / Dify are references for interaction patterns, not feature targets.
- Borrow only patterns that reduce mistakes or debugging time.
- Keep this product centered on Tasks + Workflows + Prompts; do not copy platform-scale navigation.
- Keep YAML canonical and explicit Save validation. Do NOT auto-save canonical Workflow YAML merely because other editors auto-save drafts.

[x] Hardened all API outage probes with a deterministic arm/active handshake.
    - Root cause found before another live failure: the prior 0.5s short outage could expire during the

    - All 429/502/503/raw-disconnect probes now share one Workflow fixture:
      warmup(main session) -> arm command -> execute(main session) -> validate_file.
    - arm writes api-outage-armed and waits for api-outage-active; the harness enables the proxy outage
      first, then writes the active acknowledgement so the next AI Stage starts only after the outage is live.

[x] Fixed API raw-disconnect live outage-boundary race.

      An unexplained backend/session swap still fails closed.
    - Added deterministic StageExecutor regression proving retry -> recover + Fresh Session rotation.
