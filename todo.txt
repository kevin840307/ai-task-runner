FINAL ARCHITECTURE - DO NOT RE-DESIGN WITHOUT A REAL FAILURE
------------------------------------------------------------
One runtime only:

    Chat / CLI / API / YAML List
              |
        WorkflowRunner
              |
          FlowEngine
              |
         StageExecutor
              |
             Stage
              |
          StageResult

Responsibilities:

- Stage
  - owns semantic work only;
  - returns StageResult;
  - may be AI-backed, command-backed, plugin-backed, or special-purpose;
  - may produce a producer-defined child Workflow.

- StageExecutor
  - path: runner/workflow/execution/stage_executor.py
  - owns technical reliability only:
    retry / Same Session / Fresh Session / timeout / API transient recovery /
    safety hooks / change tracking;
  - is NOT a Stage type;
  - must NOT own PASS/FAIL routing;
  - must NOT be moved back under runner/workflow/stages/.

- FlowEngine
  - owns semantic PASS/FAIL navigation;
  - owns Dynamic Handoff target navigation;
  - owns insertion/execution/resume of producer-defined child Workflows;
  - technical ERROR never becomes a graph edge.

- RunState / StateStore
  - owns durable workflow position;
  - owns durable expanded child Workflow;
  - owns dynamic task groups / role sessions / transition evidence;
  - resume must continue an already-expanded child Workflow without re-running
    its producer only to reconstruct children.

Special Stage types:

- type: review

PLAN / DYNAMIC CHILD WORKFLOW CONTRACT
--------------------------------------
PlanStage is a special Stage, not a separate workflow mode.

Parent example:

    A -> B -> C -> D

If C produces a child Workflow:

    A -> B -> C
              |
              +-> child-1 -> child-2 -> ... -> child-N
                                              |
                                              +-> D

Rules:
- any Stage may return kind=tasks or kind=stages;
- the producing Stage owns the child Stage structure;
- Runner NEVER guesses which child Stage types to create;
- Runner validates, namespaces, inserts, executes, recovers and resumes the
  producer-defined child Workflow;
- all child Stages use the normal StageExecutor reliability path;
- all child Stages finish before the parent continuation runs;
- nested producers are supported;
- child routes/Handoff targets must stay inside their child Workflow boundary;
- expanded child Workflow is durable.

PlanStage built-in behavior:
- parses/validates Plan tasks;
- PlanStage itself creates the child Stage definitions;
- current built-in child shape is alternating:
    Execute -> Review -> Execute -> Review -> ...
- Review FAIL loops only to its corresponding Execute;
- PlanStage is only one producer implementation;
- future special/plugin Stages may emit completely different child structures.

DYNAMIC HANDOFF
---------------
Dynamic Handoff is CURRENTLY SUPPORTED, not future work.

- type: handoff
- targets = explicit allow-list
- model chooses exactly one target per decision
- specialist roles remain normal AI Stages
- session_policy may be main / role / fresh / auto
- final AI validator may route FAIL back to the Handoff Stage
- durable role sessions and resume are covered by deterministic tests

Discussion / Group Chat is NOT planned.

Editor keyboard / mouse UX:
- Node: Delete/Backspace through workflow-aware delete path
- Node: Ctrl+C / Ctrl+V

- Ctrl+Z = Workflow draft undo
- Ctrl+Y / Ctrl+Shift+Z = redo
- text inputs keep native text undo behavior
- PASS edges are deletable like FAIL/HANDOFF edges; deleting PASS persists routes.pass: stop so runtime does not silently continue. Reconnecting to the flow-next Stage may be serialized compactly through flow order.
