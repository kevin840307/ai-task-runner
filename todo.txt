CURRENT ARCHITECTURE
--------------------
- One closed-loop runtime.
- Stage is the only execution unit.
- PASS / FAIL are semantic result edges.
- Technical ERROR is owned by StageExecutor and uses shared retry / Same Session / Fresh Session recovery.
- StageExecutor lives at runner/workflow/execution/stage_executor.py because it is an execution policy boundary, not a Stage type.
- FlowEngine owns semantic navigation and dynamic child-Workflow insertion.
- Workflow YAML is the canonical model used by UI / CLI / API / YAML List.
- General AI behavior uses type: base with profile: generic | execute | review.
- Special runtime semantics use dedicated Stage types such as plan / ai_validator / command / handoff / plugins.
- Any special/plugin Stage may return producer-defined tasks or stages.
- Runner validates and executes the child Workflow; Runner never guesses child Stage structure.
- PlanStage is the built-in example: it validates tasks and itself emits alternating Execute -> Review child Stages.
- Dynamic child Stages fully execute before the parent Workflow continues.
- Dynamic expansion is durable in RunState so Resume does not rerun the producer only to rebuild children.
- No public scope / task_step / type: task / type: review compatibility contract.
- Dynamic Handoff is supported.
- Discussion / Group Chat is not planned.
- Chat remains the run entry point. Workflows and Prompts are separate asset surfaces.
- Settings does not occupy primary navigation; Interface settings remain available through the existing settings entry.
- Default Chat Workflow is ralphy_ai_validate.yaml unless a still-valid user choice is already persisted.
